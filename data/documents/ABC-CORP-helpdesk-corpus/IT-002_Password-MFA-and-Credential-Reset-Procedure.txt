1. Purpose
This procedure tells Service Desk agents how to handle password resets, MFA resets, and credential-related requests for ABC CORP systems, including identity verification, escalation, and account lockout recovery.
It is deliberately prescriptive. Credential resets are the most common path attackers use to gain access to an organization, and the Service Desk is the human control point. Where this procedure says do not proceed, do not proceed.

2. Scope
In scope:
ABC CORP domain account
Email and calendar
VPN
All applications federated through the single sign-on (SSO) provider
Hardware tokens and authenticator app enrollment
Out of scope:
Applications with local credentials not federated to SSO — route to the application owner
Shared service accounts — route to IT Operations
Privileged access vault credentials — route to Information Security

3. Password standard
Active password standard for all ABC CORP accounts:
Minimum length: 14 characters
Must include at least three of: uppercase, lowercase, numeric, special character
Cannot reuse any of the last 10 passwords
Cannot contain the user's name, username, or "ABC CORP"
Expires every 180 days for standard users; every 90 days for elevated access accounts
First login on any new account requires immediate change
Note: Older documentation may reference a 12-character minimum. The 14-character standard took effect at the last revision of this procedure. If a user references the older requirement, apply 14 characters.

4. Identity verification before any reset
The Service Desk must verify identity before performing any credential action. Acceptable verification methods, in order of preference:
1. Video call with government-issued photo ID. Preferred for remote users and all elevated access accounts.
2. In-person visit to a Service Desk walk-up location with photo ID. Preferred for users at an ABC CORP office.
3. Callback to the phone number on file in the HRIS, with the caller providing employee ID and manager name. Acceptable for standard accounts during business hours.
4. Manager confirmation from the manager's ABC CORP email address. Acceptable when the user cannot complete any of the above and the manager is reachable.
Never verify identity using only:
Knowledge of the username
Answer to a security question alone
Caller ID match
A request from a personal email address
A voicemail message, regardless of content
If verification cannot be completed to one of the four acceptable methods, do not reset. Route to the Service Desk supervisor.

5. Standard password reset — agent steps
1. Open the identity management console.
2. Search for the user by username or employee ID.
3. Confirm account status. If the account is disabled, do not reset. Route to IT Operations for status check first.
4. Complete identity verification per Section 4. Record the verification method in the ticket.
5. Issue a temporary password via the console's reset function. The system generates a one-time password valid for 45 minutes.
6. Communicate the temporary password to the user via an approved channel — never email. Use the console's secure delivery or read it aloud on a verified call.
7. Instruct the user to log in and set a new password immediately. Confirm successful login before closing the ticket.
8. Add a ticket note with the verification method, reset timestamp, and confirmation of successful login.
Decision points:
If the account has had three or more resets in 30 days, add a note flagging the pattern and notify the user's manager.
If the user reports they did not request a reset, treat as possible compromise and route to SE-002 without resetting.

6. MFA reset — agent steps
1. Verify identity per Section 4.
2. Confirm the MFA method being reset: authenticator app, hardware token, SMS, or push.
3. If the user has lost a hardware token, do not reset until the token is reported lost in the asset register. This prevents a second token being issued while the first is still active.
4. Remove the existing MFA method in the identity console.
5. Guide the user through re-enrollment on a verified call or in-person session.
6. Confirm successful enrollment by asking the user to complete one authentication.
7. Document the reset reason and method in the ticket.
Push notification fatigue: if the user reports receiving repeated unexpected push prompts, treat as an active MFA push attack. Do not reset. Escalate to Information Security immediately.

7. Account lockout
Accounts lock after five consecutive failed attempts and unlock automatically after 30 minutes. If a user cannot wait:
1. Verify identity per Section 4.
2. Unlock in the console.
3. If the account has locked three or more times in seven days, do not simply unlock. Check for a stale credential on a mobile device or scheduled task. Escalate to IT Operations if suspected.

8. Privileged and elevated access accounts
Password and MFA resets for elevated access accounts follow the same verification plus:
Notification to Information Security within one hour of the reset
Confirmation with the account holder's manager before restoring access
Vault check for any shared credentials before issuance
Reset is logged in the privileged access log in addition to the ticket
Elevated access resets outside business hours require Service Desk supervisor sign-off before proceeding.

9. What agents must not do
Reset a password based on a request from a personal email
Reset a password based on a phone call alone without verification
Read a temporary password into a voicemail
Reset MFA for a hardware token without logging the token as lost
Bypass MFA for convenience during business hours
Share temporary passwords across tickets or chat channels
Reset a password for an account whose holder is not the person on the call
Override the 45-minute temporary password expiry

10. Escalation
Escalate to the Service Desk supervisor if:
Identity verification cannot be completed to standard
The user disputes account ownership
The reset is for an elevated access account outside business hours
The user has a suspected compromise — route to SE-002, do not reset
The user reports repeated unexpected MFA prompts
Escalate to Information Security if:
The account shows signs of active compromise
The user is the target of a suspected MFA push attack
Multiple reset requests arrive for the same account within a short window
